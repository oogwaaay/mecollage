实现契约 & 与当前实现的差距

已落地（工作区，未提交）：

  • blog/index.html：.blog-search-panel + label/input + #blogSearchResults（role=status aria-live=polite）+ #blogSearchEmpty + #blogSearchClear。
  • assets/js/blog-search.js：渐进增强、标题+描述匹配、AND 分词、CJK 原样、Esc 清除、window.mcBlogSearch 暴露。
  • components.css §20：input 44px pill / results / empty / clear 全部 token 化。
  • i18n/{en,zh,zh-tw,ja,es}.json：placeholder / results / result_one / empty / clear 5 个键。

本原型补的设计缺口：

  • 无结果时给 建议话题（mobile / square / holiday），降低再次空结果概率。
  • 命中高亮（当前实现不做，属可选增强；需注意 CJK 与性能）。
  • 移动端搜索框与标题的间距/首屏占位（当前 CSS 已是 margin: space-3 auto space-5）。
  • 结果数的“1 result / N results / 8 articles”三种文案与 i18n 键映射（当前 JS 只在有查询时显示）。

不做：不使用 ?q= URL 参数、不改 history、不新增后端、不改文章链接/URL/canonical（与 R2-B 约束一致）。

D1
搜索是否需要 URL 状态？推荐 不做：加 ?q= 会产生可索引重复页、需 canonical/hreflang 处理（L-05 风险），收益低。搜索是“找内容”的辅助路径，不是落地页。
D2
是否做命中高亮 / 分类筛选？高亮为可选增强（P2 级）；分类筛选可作为 R2-B 后续（需新增 data-category 与一组 i18n 键）。本轮只做标题+描述过滤，保持 8 篇规模下的简单可靠。
D3
i18n 文案责任5 个键已入 5 份 JSON；新增“建议话题/命中提示”文案需同批补 5 语言（L-02）。缺键时 JS 英文兜底，不显示裸 key。
D4
可访问性验收结果数 aria-live=polite、空状态可聚焦、清除按钮 44px、Esc 清除、无 JS 全部可见；functional/check-layout 需覆盖这些断言（L-35：行为变了要同步验收）。
实现落点：R2-B 已实现主体（blog/index.html + assets/js/blog-search.js + components.css §20 + 5 语言 i18n 键）；本原型只补空状态建议与“默认态结果文案”设计。 门禁：token audit（JS 不写视觉值）+ check-layout（移动 390 无溢出、44px）+ SEO harness（8 个文章链接/canonical 不变）+ functional 回归。
